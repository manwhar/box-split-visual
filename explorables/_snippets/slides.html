Demo snippets

How a demo page works with the deck: one mechanism per slide.

Each demo is its own small page in this folder. Read its source beside the slide that shows it.
1

A canvas that stays sharp, and pauses

canvas/index.html listens for deck:resolution and deck:visibility.

The deck scales this frame up to fill the slide. Without deck:resolution, the canvas would be drawn at its own size and stretched, so it would blur. Move to the next slide and back: the animation stops while the slide is off screen.
2

One page, chosen by its address

variants/index.html?variant=few shows 20 coin flips.

One page can serve several slides: the slide picks what it shows with a query parameter. Its first view comes from a fixed seed, so the slide looks the same every time, including in its preview picture.
3

The same page, side by side

Two frames in one play-set scale together.

Each frame is a separate page with its own controls: Flip again in one doesn't change the other. When a comparison must stay in step, draw both views in one page instead.
4

Replaying a recorded run

recording/index.html loads run.json, and says it's a recording.

The published site is static files, so a demo can't call a model or a server: record what it needs and keep the file in the demo's folder. The page says it's loading, says plainly if the file is missing, and labels the replay as a recording so nobody takes it for a live computation.
